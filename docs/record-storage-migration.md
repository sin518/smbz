# 盘局记录存储迁移说明

## 范围

本次迁移增加稳定身份、计算版本、生命周期和软删除字段，并将浏览器本机记录从全局 `localStorage` 切换到按账号隔离的 IndexedDB。迁移文件不会由应用代码自动执行，也未在本次改动中连接或修改任何线上数据库。

## 数据库执行前

1. 备份 `BaziProfile`、`BaziChart` 和 `DivinationRecord`。
2. 在与生产结构一致的测试库执行 `migration.sql`。
3. 确认新增列允许空值，旧客户端仍能写入。
4. 检查新增的两个部分唯一索引和两个查询索引均已创建。
5. 运行后端同步测试，并用两个不同 `localId` 上传同一 `recordKey`，确认返回同一 `serverId`。

成功标志：旧记录仍可读取；新记录带有身份和生命周期字段；删除后旧后台上传返回 409。

## 浏览器旧数据迁移

记录页只展示迁移预览，不会静默归属、上传或删除旧数据。

1. 用户点击“复制到待认领区”。
2. 应用按稳定身份合并重复项：保留最早创建时间和最新内容。
3. 复制完成后逐条校验 `recordKey`，只有全部校验成功才写入完成标记。
4. 同时保存 `sourceId -> targetId + recordKey` 收据，便于审计重复项如何合并。
5. 登录用户再次明确点击“导入当前账号”后，记录才进入该账号空间。
6. 原 `localStorage` 键在当前兼容期内保留，便于回退。

成功标志：账号 A、账号 B、游客和待认领区互不可见；中途失败时可安全重试。

## 回滚

前端回滚时可恢复旧版读取代码，因为原 `localStorage` 数据未被自动清理。数据库回滚脚本位于同一迁移目录的 `rollback.sql`。

执行数据库回滚前必须再次备份。`rollback.sql` 会删除新增字段，因而会丢失迁移后产生的身份、墓碑和生命周期元数据；应先停止新客户端写入，再确认无需保留这些元数据。

## 已知边界

- 云端旧记录在客户端读取时按稳定身份折叠显示；数据库中的旧空身份行不会在没有运维预览的情况下被批量物理删除。
- 新提交或重新同步旧记录时，服务端会逐步补齐稳定身份。
- 软删除墓碑目前保留，不做静默压缩。
